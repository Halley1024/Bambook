# 2026-09-14

## 评估：Tauri → Electron + Go 迁移可行性（仅分析，未动代码）

用户提出把 Bambook 从 Tauri v2 + Rust 迁到 Electron + Go，要求先评估复杂度和前端改动面。

### 项目量化基线（本次实测）
- 前端：153 个 TS/TSX 文件 / 10,979 行；CSS 21 个文件 / 5,299 行
- 后端：`src-tauri/src` 120 个 .rs 文件 / 11,456 行
- 注册 Tauri 命令：58 个（`src-tauri/src/bootstrap.rs` 的 `generate_handler!`）
- 前端 IPC 调用点：63 处 `invokeCommand<T>()`
- MuPDF：`native/mupdf-sys`（vendor MuPDF C 源码 398 个 .c）+ `native/mupdf-rs` 0.8（safe wrapper 90+ 模块）+ `native/libclang`

### 关键结论
1. 前端迁移面极小：全项目**仅 8 个文件** import `@tauri-apps/*`。
   - `src/platform/tauriClient.ts`、`fileDialog.ts`、`window.ts`、`localLlmClient.ts`
   - `src/app/layout/AppShell.tsx`
   - `src/features/documents/repositories/documentRelink.ts`
   - `src/features/documents/components/StartWorkspace.tsx`
   - `src/features/markdown/MarkdownWorkspaceProvider.tsx`
   - 另需改 `package.json`、`vite.config.ts`
   - 前 3 处是 `@tauri-apps/plugin-dialog` 的 `message()` 弹框，属最容易替换的。
   - 原因：README 设计原则第 3 条（IPC 统一封装在 repository/platform 层）被真正执行，`invokeCommand` 是唯一 IPC 缝。
2. 前端两个真正的设计点：
   - `localLlmClient.ts` 用 Tauri `Channel` 做流式；Electron 无对应物，需 `webContents.send` + requestId 自建事件流。
   - `AppShell.tsx` 的 `onCloseRequested` 拦截式关闭 → 主进程 `win.on('close')` + preventDefault + 与渲染进程往返，需保护 `closeCoordinator.ts` 的两阶段事务。
   - 隐藏坑：HTML5 拖放打开文件。Tauri v2 默认关原生拖放所以 `text/uri-list` 可用；Electron 默认吃掉拖放事件，且 Electron 32+ 移除 `File.path`（须用 preload 的 `webUtils.getPathForFile`）。
3. 后端是重写而非迁移：
   - `domain/` 纯 Rust 无 Tauri 依赖，可机械移植（serde→encoding/json、thiserror→自定义 error、windows-sys `MoveFileExW`→`golang.org/x/sys/windows`）。
   - IPC 壳要重建（约 1,000–2,000 行）：Go sidecar 子进程 + stdio JSON-RPC/localhost HTTP、进程生命周期、崩溃重启、requestId、流式、二进制载荷。`CommandError` 的 `code` 枚举是前端控制流契约，必须逐字保持。
4. **最大阻塞是 MuPDF**：Go 无 mupdf-rs 等价物；MuPDF 的 `fz_try/fz_catch`（setjmp/longjmp）在 cgo 中比在 Rust FFI 中更危险（Go runtime 不支持 longjmp），需重写 C bridge；且 MuPDF 在本项目是两用的（PDF 渲染/文字/搜索 + Markdown→PDF 导出），换不掉。
5. **战略冲突**：README 第 1 节目标是 Windows/macOS 桌面 + Android/iOS 平板，而 **Electron 完全不支持 Android/iOS**。走 Electron 等于放弃四端路线。此外会丢掉 Tauri 的体积（WebView2 复用）与内存优势。
6. 更便宜的替代路线：保留 Tauri + React 外壳，只用 Tauri v2 的 sidecar（`externalBin` + `tauri-plugin-shell`）把 Rust 后端换成 Go 二进制。前端几乎不用改，不丢移动端，但 MuPDF 问题依旧存在。

### 建议的下一步验证
写最小 Go+cgo MuPDF 试验：打开 PDF → 取一页文字 → 渲染一页 PNG → 导出。成功则迁移只是工作量问题，失败则说明方向不可行。
